# Small editors, taggers, grammar correctors and normalization components

Research collected October 30, 2026. This lane inspected 50 Hugging Face model identifiers, resolved 46 current repositories, and reviewed 11 architecture/component families. It downloaded metadata, cards, configurations and license texts only. **No model weights, exports or inference benchmarks were run.** Artifact SHA-256 values in the catalog are publisher LFS metadata, not independent full-download verification. The four unresolved identifiers are retained as failed leads rather than quietly counted as usable models.

The strongest result is that a useful low-memory lane exists beyond causal chat models: published edit-taggers can classify keep/delete/punctuation/case actions in a single encoder pass. However, existing small artifacts differ substantially in coverage, provenance and integration work. None inspected proves Freehand's 650,000,000-byte whole-app / 700 ms complete-delivery limits.

### SmolLM2 Post-ASR 135M and 360M

Both cards declare Apache 2.0 and name the Apache-licensed SmolLM2 instruction bases. The published 135M Q4 file has LFS SHA-256 `c2ea857ceade00e134d38a1692939a761c190a7b9daf72b8307aa8ca0794a467`. The 360M artifact is 270,591,008 bytes, SHA-256 `1a06422aafa97ea69a7bf95837c7bebb83a2d4ca55006010442dd768247f27dd`, at revision `970914e731d64710407e1cf70e3a8886269b5ae2`.

Use the exact published ChatML system text and `<|task:clean_punctuate|>` task token, greedy decoding and the documented `<|im_end|>` stop. The other task tokens request email layout, action bullets or neutral paraphrase and would confound fidelity evaluation. The cards describe DoRA fine-tuning/fused weights but do not supply an independent cleanup benchmark or enough dataset provenance to infer reliability. The small file is an observed artifact; good output is an experiment still to run. [135M source](https://huggingface.co/vikramlingam/SmolLM2-135M-Post-ASR-Engine/blob/c926e4c06cfc458892d37a16ef032a0a98bd77b2/README.md), [360M source](https://huggingface.co/vikramlingam/SmolLM2-360M-Post-ASR-Engine/blob/970914e731d64710407e1cf70e3a8886269b5ae2/README.md).

### Meg v1

The actual graph is 26.77 decimal MB, or 25.53 MiB. That is a file size, not a measured incremental process footprint. Its card describes an approximately 33M-parameter, eight-layer encoder with four input tensors: `input_ids`, `attention_mask`, ten-bin ASR confidence and four-bin acoustic pauses. It predicts token action, punctuation, casing and BILOU reparandum-span labels.

The quickstart supplies default confidence/pause bins for text-only input and manually changes bins for selected filler words. That is a different condition from real aligned acoustic features. Freehand's current cleanup interface supplies final text, not those aligned features. The published example also stops at output logits rather than providing the entire text reconstruction and claimed AST validator. We have not established that the card's 1.87 ms median, 3.23 ms p95, 100% entity preservation, or zero unnecessary edits generalizes beyond its publisher's challenge set. In particular, a regularizer cannot mathematically guarantee zero edits on every future clean sentence. Treat the graph as promising and the claims as hypotheses. [Pinned model card](https://huggingface.co/vikramlingam/meg-v1-tagger-int8/blob/cbf6f6a9b05efe85b4af5cae0e941db8c250d83e/README.md).

### Typurr and Mów

Typurr's card declares Apache 2.0 and uses DistilRoBERTa with first-subtoken labels. It claims approximately 150 ms CPU inference through Rust `tract` for a fixed 96-token ONNX graph. Its advertised Windows application repository returned 404 during this research, so available weights are verified but the application's current deployment path is not. Reject/bypass overlength inputs transparently; splitting at 96 tokens would conceal long-range correction failures. [Pinned card](https://huggingface.co/JasonIr/typurr-edit-tagger/blob/558c5ef0dc789fd5b1042151bedbc7a3a0b5fa0c/README.md).

Mów's derivative declares CC BY 4.0 and claims the same license for its source fine-tune. The pinned upstream `arielcerdap/modernbert-base-multiclass-disfluency-v2` card does **not** contain an explicit license declaration. Its ModernBERT base is a further step upstream; the base license alone does not settle the fine-tune grant. The model card's deployment link points to Mów, but that application's inspected README describes a generative SLM route rather than proving this classifier is active. Its five deletion classes are useful for a narrow, measurable baseline without inventing words; they do not repair subject agreement or add punctuation. [Converter card](https://huggingface.co/sam-castro/mow-disfluency-classifier/blob/e1f59b45e03988dd55b8ff307c602f0d4567bf8c/README.md), [upstream card](https://huggingface.co/arielcerdap/modernbert-base-multiclass-disfluency-v2/blob/bb56bf6b789b94faa126c953499fa138137d602c/README.md), [application source snapshot](https://github.com/krokoko/mow/blob/15a518d6e03935ce57d1dd2ab7366671b629c3cc/README.md).

### Mend, Hem and Looma

Mend has unusually useful disclosed negative evidence. The publisher trains on 50,000 synthetic pairs plus 25,000 real Switchboard utterances and splits evaluation by conversation. It reports real-speech repair resolution improving from 0.326 to 0.503, but admits that roughly half of real repairs remain unresolved. A published example deletes a meaningful discourse phrase. No actual recognizer hypotheses were used in training, so ASR substitution robustness is unproved. The full source also corrects a misleading earlier claim about filtering cut-off words: the intended filter did not work. Prefer that source over the older model-card summary when describing fragments. Use `clean up: ` with lowercased input and edge punctuation removed; that preprocessing conflicts with exact case-sensitive technical/dictionary literals unless the adapter explicitly protects them. Fine-tune code/card declare MIT; the Google base license and disclosed data attribution remain separate obligations. [Pinned model card](https://huggingface.co/daltonoscar0/mend-flan-t5-small/blob/230a456089ac0c03d331546a56a5ac2ed9f26271/README.md), [full source](https://github.com/daltonoscar0/mend/blob/605c30b7c1241f5c3e7680942ea6a055912ac387/README.md).

Hem intentionally turns clean script into disfluent speech, with control tokens for disfluency intensity. It could support a separately audited synthetic-data experiment, but is an exclusion for direct cleanup. [Hem card](https://huggingface.co/daltonoscar0/hem-flan-t5-small/blob/f04b92a6a8f093b45e2aeb9e4f63a1aeefe2fb2b/README.md).

Looma uses `fix grammar: ` and declares Apache 2.0. It gives training loss and demonstrations rather than a representative held-out fidelity benchmark. Its FP32 metadata is 76.96M parameters / 307.87 MB. The card's smaller INT8 estimate is hypothetical and not an available checkpoint. The pinned config sets `use_cache: false`; any speed comparison must record that and treat changing it as a separate runtime ablation. Do not repeat its training-loss numbers as semantic accuracy. [Card](https://huggingface.co/tsilahi/looma-dictation-slm/blob/e1598108b1c4d7020d183c5b34752dd62cfdc847/README.md), [config](https://huggingface.co/tsilahi/looma-dictation-slm/blob/e1598108b1c4d7020d183c5b34752dd62cfdc847/config.json).

## Existing edit-tagging architectures and ready grammar graphs

[GECToR](https://github.com/grammarly/gector/blob/3d41d2841512d2690cffce1b5ac6795fe9a0a5dd/README.md) uses bounded edit labels rather than writing every output token. Some variants require several apply-and-retag rounds, so a single forward-pass claim must not be extended to the complete iterative pipeline. It demonstrates an architecture, not semantic safety: deleting a negation or intentional repetition is still a meaning error.

[DeepQuill's grammar graph](https://huggingface.co/deepquillapp/gector-grammar/blob/2232e0ef109dd12e11e2c74b565b7318e36379e4/README.md) is a particularly useful commercial-provenance reference. It explicitly lists a clean-corpus training recipe and avoids common research-only GEC corpora/checkpoints. Its 256,279,090-byte graph stores FP16 weights but casts them to FP32 at load, so low disk size does not establish low resident memory. It targets fiction grammar, not raw spoken false starts. Keep it as a possible grammar component or recipe, not a full cleanup winner.

[LiquidAI's LFM2.5 Encoder 350M Spellchecker](https://huggingface.co/LiquidAI/LFM2.5-Encoder-350M-Spellchecker/blob/4e2f724c10985e9ec90f34189c22be5d5f2e41e0/README.md) is an official GECToR-style encoder fine-tune with grammar/spelling/punctuation/casing coverage. It has 713,449,656-byte FP16 weights; example code casts to FP32 and loads custom Python with `trust_remote_code`. It expects punctuation-separated whitespace tokens and supports repeated refinement. This needs a source audit and deployment/export work; it is not a causal GGUF drop-in or established small-CPU option. The card's usage example omits the `M` in the model identifier, so use the observed repository ID rather than copying that typo. Its LFM license is separate from Apache/MIT.

The broader architecture literature remains relevant if ready small candidates fail:

- **[LaserTagger](https://github.com/google-research/lasertagger/blob/0bfa546e755814b28163dad039ab6d9f53f82bb8/README.md):** keep/delete plus a learned phrase vocabulary; optional sentence swapping. The documented pipeline fine-tunes BERT for a chosen task. A generic BERT initializer is not an already-trained dictation editor. Code is Apache 2.0.
- **[FELIX](https://github.com/google-research/google-research/blob/8203b76e5ed6d6393a3296be67f59d835ae46c73/felix/README.md):** separate tagging/pointing and insertion models. The inspected repository gives training steps and a DiscoFuse example, not a ready English dictation checkpoint. Code is Apache 2.0.
- **[Seq2Edits](https://aclanthology.org/2020.emnlp-main.418/):** generates span edits, reducing autoregressive work when changes are sparse. The primary paper reports task-dependent speedups; no ready English dictation checkpoint was verified. Its implementation is in [Tensor2Tensor](https://github.com/tensorflow/tensor2tensor/blob/master/tensor2tensor/models/research/transformer_seq2edits.py), not the nonexistent Google Research path initially probed.
- **[EdiT5](https://aclanthology.org/2022.findings-emnlp.156/):** parallel tagging/reordering followed by autoregressive insertion. It is a future architecture/training option, not an established ready-weight shortcut in this survey. Published cross-task speedups do not predict our Windows timing.
- **[FastCorrect](https://github.com/microsoft/NeuralSpeech/blob/8cf4fbcbf451c3affc68ecfa6c970327e927062f/FastCorrect/README.md) / [FastCorrect2](https://github.com/microsoft/NeuralSpeech/blob/8cf4fbcbf451c3affc68ecfa6c970327e927062f/FastCorrect2/README.md):** non-autoregressive ASR correction; the released example models are Chinese character-based. FastCorrect2 also uses multiple ASR hypotheses, beyond the current final-text interface. An English dictation deployment would require new training/adaptation and different inputs. Repository code is MIT; data/checkpoint grants must be traced separately.

## Punctuation, casing and finite-state normalization

[Edge-Punct-Casing](https://github.com/frankyoujian/Edge-Punct-Casing/blob/c154bf777427f4549dfb56a0e9f696aae6136616/README.md) is a CNN-BiLSTM punctuation/casing model already supported by sherpa-onnx. The [official sherpa documentation](https://k2-fsa.github.io/sherpa/onnx/punctuation/pretrained_models.html) lists an approximately 7.1 M INT8 graph plus 146 K BPE vocabulary, or a 28 M FP32 graph. Its complete release archive is 30,667,839 bytes because it includes more than the minimal INT8 deployment. The API example's 13 ms CPU observation is an example, not a Freehand benchmark. This is an excellent narrow baseline: it preserves vocabulary through bounded formatting operations, but does not remove false starts, correct grammar or resolve a later changed recipient. Before bundling, inspect the exact model archive's notices rather than inheriting the code license automatically.

The larger Chinese/English CT-transformer punctuation model is also supported. It is less attractive for English-only cleanup; the official English example shows full-width punctuation. Both are punctuation components, not substitutes for full repair handling.

[NVIDIA NeMo text processing](https://github.com/NVIDIA/NeMo-text-processing/blob/ddadfb2a38d2bc6b8cc6232c4f915eb60f500688/README.md) offers Apache-licensed WFST normalization grammars. These can render spoken numbers, dates, money and other semiotic classes without a generative LLM. They do not decide arbitrary semantic corrections or repair grammar. Freehand already has deterministic English number formatting and dictionary correction; replacing those is not necessary just to add cleanup. Separate prebuilt [Riva NGC grammar packages](https://catalog.ngc.nvidia.com/orgs/nvidia/tao/models/inverse_normalization_en_us/-) carry Riva terms, so an Apache code license is not a blanket license for every downloaded FAR file.

[NVIDIA's Thutmose tagger](https://docs.nvidia.com/nemo-framework/user-guide/24.12/nemotoolkit/nlp/text_normalization/text_normalization_as_tagging.html) provides a neural, single-pass ITN checkpoint (`itn_en_thutmose_bert`). It addresses spoken-to-written normalization, not the full disfluency/self-correction/grammar task. It is a future normalization comparison if the existing deterministic formatter becomes a bottleneck. [LanguageTool](https://github.com/LanguageTool-org/languagetool/blob/8f829976b5e8bed9023ed9fdcbc6246efb697388/README.md) similarly supplies a local rule-based grammar checker rather than a spoken-repair resolver, with Java runtime/resource costs and LGPL code terms to consider separately.

## Licensing and artifact traps that affect the shortlist

1. **Official CoEdIT weights are noncommercial**, while the CoEdIT dataset card declares Apache 2.0. `jbochi/coedit-small` is a separately trained Apache-declared model; do not group these rights by family name. [Weights](https://huggingface.co/grammarly/coedit-large/blob/5637bcdf9d8d4419f97c8cfea36f7d35c79232b6/README.md), [dataset](https://huggingface.co/datasets/grammarly/coedit/blob/e9a255c33ef910bc33a9d2b522653fa87521583e/README.md).
2. **GECToR conversion tags can broaden the license incorrectly.** The [gotutiyan source card](https://huggingface.co/gotutiyan/gector-roberta-base-5k/blob/adaac6fb919431fb5a038b1e449055ae638613a4/README.md) explicitly restricts its weights to noncommercial use. The [letheviet conversion](https://huggingface.co/letheviet/gector-roberta-base-5k-onnx/blob/b631ea729bf21a748ee19d9240f04d14e8f2c36d/README.md) says MIT, whereas [another conversion](https://huggingface.co/Zaid-Hossain/gector-roberta-onnx/blob/090bbffce6ebae66186313105b70242e3ee9252a/README.md) explicitly preserves the upstream restriction. Follow the source grant, not the convenient conversion tag.
3. **Tiny ONNX files can be graph shells.** Letheviet's 1,307,959-byte graph requires a 511,719,424-byte external data file: 513,027,383 bytes before tokenizer/runtime. Its README's approximately 1.5 MB packaging suggestion omits those weights. Every selected encoder/decoder/external-data file must be counted.
4. **Peter Szemraj’s license metadata needs interpretation, not automatic rejection or permission.** The source card lists two licenses but explicitly assigns NC-SA to its JFLEG-derived dataset and Apache 2.0 to the model. Record both declarations and seek provenance clarity for redistribution. Its [TonyRaju INT8 derivative](https://huggingface.co/TonyRaju/pszemraj-grammar-synthesis-small-onnx-int8/blob/dabfdad096972dd4daf20b2cb0b102c0c61ed6d4/README.md) itself declares NC-SA and explicitly warns that all 50 test outputs became incoherent after quantization. Exclude that artifact on known quality evidence regardless of its attractive speed/size.
5. **Kotoshu's ready 128,754,456-byte INT8 graph is research-only**, with explicit NC-SA and research-corpus restrictions, even though its application code is BSD. [Card](https://huggingface.co/kotoshu/grammar-en/blob/3189cc62fdbaff6e5007a16ec52e72d687127232/README.md).
6. **The LaMini-named ASR corrector is not license-cleared by its bare MIT tag.** Its card provides no training or prompt details; the named [LaMini 77M base](https://huggingface.co/MBZUAI/LaMini-Flan-T5-77M/blob/c5b12d50a2616b9670a57189be20055d1357b474/README.md) is CC BY-NC. Actual lineage and rights require clarification rather than assuming the fine-tune name proves either permission or restriction.

Dataset license terms, trained weight grants and implementation licenses are separate facts. This report records publisher declarations and specific conflicts; it does not infer that every data license automatically attaches to every trained model, or that a permissive base license automatically grants every downstream fine-tune.

## How to test this lane without changing the product contract

First run the published contract exactly, keeping raw logits/generated text separate from reconstructed/provider text and Core's accepted output/fallback. Do not give a model credit for bytes restored by code, existing number formatting, manual acoustic-bin heuristics or a later fallback.

For edit-taggers, an offset-based edit plan is promising: run on the original tokenization, propose bounded changes, reject edits that touch protected dictionary ranges, then reconstruct with original untouched spans. This avoids asking a model to retype technical literal bytes. It still cannot prove that removing an unprotected negation or emphasis preserves meaning. Strict protection also retains the existing coverage limit when a legitimate correction removes an obsolete protected clause.

The first screen should contain meaningful versus filler uses of words such as “like”, “well”, “actually” and “basically”; intentional repeated emphasis; contradictory negation repairs; later changed dates/numbers/recipients; quoted instructions/questions; technical paths/identifiers/Unicode; already-clean text; and repairs near/beyond the model's context limit. A tagger's closed operation vocabulary must be scored for both useful coverage and false deletions. Do not silently truncate, chunk away a late correction, normalize away protected whitespace, or modify dictionary semantics to manufacture a pass.

Run the smallest GGUF specialist with the existing worker route before investing in a new runtime. In parallel, a separate bounded ONNX tagger proof can test whether the latency/RAM path is practical. Mend/Looma require a seq2seq adapter and a validated native export/quantization; a Python quality screen is useful, but Python/PyTorch memory is not a prediction of the final .NET/native package. Reusing or coordinating ONNX Runtime must respect Freehand's pinned sherpa/runtime versions rather than introducing an incompatible DLL silently.

The current public held-out fixtures have already influenced selection and diagnosis. Treat them as validation/regressions; freeze a candidate before evaluating a new, independently authored final holdout. Measure whole-app Windows host memory plus shared GPU memory, report dedicated VRAM separately, and include actual complete text delivery. Per-sentence Apple CPU timings, first-token speed, file size, or a standalone Python graph do not establish that SLA.
