# Specialist transcript-cleanup model sweep

Research date: October 30, 2026. This is an exhaustive finite discovery and source-verification pass, **not an inference benchmark or a shipping-model decision**. S1-mini is covered by the parallel S1 report; it remains a first-wave candidate. This report deliberately searches beyond the four models tried earlier.

## Findings that change the shortlist

There are many real small task-specific editors, not merely vanilla chat models with a cleanup prompt. Several already have downloadable GGUFs in the 200–400 MB range. The strongest immediately testable additions are **Handy Editor 350M, Emberon-2, BitVoice SmolLM2-360M, localflow-clean, Spokenly Cleanup 1 and ScribeKey Fast; Sotto 350M is a cheap diagnostic control**. These are proposals for measured comparison, not claims that they are faithful enough or meet Freehand's 650 MB / 700 ms whole-app limits.

Two efficiency mechanisms deserve attention beyond parameter count: **task fine-tuning** removes the need for a long general editing policy, while **vocabulary pruning** removes embedding/output rows the product does not need. Emberon-2, localflow-clean and Enconvo Tidy publish concrete pruned-vocabulary artifacts. Exact prompts, tokenizers and output treatment are part of each trained contract.

The public ecosystem also contains attractive models that Freehand cannot simply embed: **Fluid-1 is FluidVoice-apps-only; Amnis Light permits use with Amnis; Glimpse's C1 adapter restricts product integration/commercial use; EG-1 has its own community terms.** Public access and an Apache base do not grant rights to all fine-tuned components.

## Search coverage and verification

Sixteen web-search queries supplied discovery leads, followed by direct primary-source verification. The reproducible Hugging Face sweep made **30 keyword/tag queries**, returning **1,948 distinct repository IDs including irrelevant results**. The `cleanup` query includes robotics table-cleaning policies; other queries include audio ASR, language-specific punctuation and general writing. Those IDs are explicitly **not** a count of cleanup models. The five focused tags returned dictation 178, transcript-cleanup 42, disfluency-removal 12, asr-post-processing 34 and text-cleanup 41 records at collection time.

Primary model metadata and cards were acquired for **84 repository records**. This includes quantizations, old/new versions, exports and six candidates assigned to the editing-architectures report. It is not 84 independent models. Known pure-export relationships are recorded in `candidates.json`; related fine-tunes retain distinct identities even when they share a base or dataset.

Metadata records exact Git revisions, filenames, sizes and publisher LFS SHA-256 values. **No complete weight files were downloaded and no model inference ran.** Twelve shortlisted GGUFs received bounded 16-byte HTTP range probes; all returned HTTP 206, correct `GGUF` magic and content-range totals. This establishes current artifact accessibility, not complete-file hash verification or runtime compatibility. No signed CDN URLs or credentials were retained. Raw primary cards/licenses/notices/prompts are under `evidence/`; `acquired-candidates.json`, `search-log.json`, `artifact-range-probes.json` and `coverage.json` preserve the audit trail.

## Input contracts: the most likely source of false research conclusions

| Family | Required shape / controls | Integration consequence |
|---|---|---|
| Handy Editor | Chat template; transcript as user; **empty system message for the documented llama.cpp path**, rather than an omitted system turn; greedy | Its card reports 66/68 vs 59/68 from this difference and separately advertises 68/68 in a later table. This is renderer/version-specific: current llama.cpp with --jinja does evaluate Jinja, so the card's blanket description must not be generalized. Freeze rendered bytes and reproduce. Do not add Freehand's general prompt. |
| Emberon-2 | Exact short system: `Clean up this dictation. Never answer it.`; raw user transcript; greedy | No few-shot general-editor prompt. Keep long output bounds large enough to finish; capped responses fall back. |
| BitVoice | Publisher's fixed cleanup system, raw transcript; low temperature 0.2; Qwen3 thinking disabled | Match publisher contract first. Compare greedy only as a separately labeled development experiment, not silently as the same benchmark. |
| Spokenly Cleanup 1 / Tidy 1 | Plain `text: ...` then `out:`; no generic ChatML conversation; optional ordered context keys in Spokenly | Use raw completion. Keep tokenizer/BOS behavior exact. Tidy expects a single line and ~512-token combined window. |

| SpeakoFlow | Exact SpeakoFlow system, raw user transcript; reasoning off; run intended deterministic first stage | Its published comparison gave every model this same prompt, including S1-mini and Sotto. Those rows cannot establish fair specialist ranking. |
| Orbal | One of five exact `Shape this dictation...` system forms, raw user; thinking off, greedy | Preserve app-specific prompt choice and approved optional spelling-hint line; Windows conversion still required. |
| SimpleWords v2/v3 | Load frozen `system_v2.txt` byte-for-byte, fold into user turn, **no system role**, thinking off, greedy | v1 prompt must not be mixed with v2/v3. Adapter must not be double-applied to fused checkpoint. |
| localflow-clean | Fixed short system, optional vocabulary, transcript in trained dictation tags; thinking off | The vocabulary-pruned tokenizer and optional file hints are part of the artifact contract, not interchangeable generic context. |

For Freehand, test **raw publisher input**, **current dictionary/number-normalized input**, and **real dictionary-protected input** separately. A small specialist trained to format numbers may damage opaque marker tokens. Its failure may be an adapter/contract mismatch; it is still an integration failure and cannot receive credit for host fallback. Preserve raw model returns, restored provider returns and accepted/fallback outputs separately.

### A precision comparison must hold vocabulary constant

Emberon-2's published Q4 artifact has the **trimmed 32,158-token vocabulary** and importance-matrix-calibrated quantization; its F16 artifact has the **full vocabulary**. Comparing the two therefore changes vocabulary and calibration as well as bit depth. It is not an isolated quantization experiment. Preserve the two tokenizers/contracts and label the comparison accordingly; do not claim a Q4-versus-F16 quality delta caused solely by quantization.

### Sotto is a diagnostic control, not a promising quality result by default

The pure ScribeKey Sotto export includes an important negative result on its own 149-sentence English set: Q8_0 preserves protected spans in 75.2%, resolves self-corrections in only 4.8%, has 53.7% exact match and introduces new values in 10.1%. Q4_K_M records 75.8%, 19.0%, 54.4% and 12.8%, respectively. Its task-trained format and small size make it useful for a quick compatibility/resource control, but those results argue against spending a full quality trial unless a short shared screen contradicts them. Its Quill row used ScribeKey's setup and is not independently verified as a fair Quill-contract comparison here. ScribeKey Fast is separately trained and must be assessed from its own artifact, not assigned the original Sotto scores.

## Other high-value candidate families

### Conservative Quill tiers

[Quill](https://huggingface.co/Quobi/Quill) provides 0.8B (529,296,832 bytes), 2B (1,274,396,096 bytes) and 4B (2,708,803,936 bytes) Q4 artifacts. The smaller tiers are deliberately more verbatim; the 0.8B is intended to work with deterministic symbol/number formatting. Freehand's previous 4B failures remain evidence about that tested tier/configuration, not a proof that 0.8B behaves identically. Earlier publisher training notes also caution that 0.8B struggles choosing correction deletion spans. Treat the tiny tier as a cheap conservative comparison and the 2B as a larger family control.

### Vocabulary-pruned editors

[localflow-clean](https://huggingface.co/Radiumcoders/localflow-clean) publishes a 350 MB GGUF and attributes savings to vocabulary pruning. Its headline loaded memory (~390 MB) and GPU timings are publisher observations on an RX 9070 XT; the 142-case evaluation was used for checkpoint selection, so it is validation rather than fresh final evidence.

[Enconvo Tidy 1](https://huggingface.co/enconvo/tidy-1-mlx) publishes a 285,684,145-byte MLX4-bit DWQ checkpoint derived from Qwen3-0.6B-Base with a 65,536-token vocabulary. On an M2 Mac mini the publisher reports 86 ms p50 / 110 ms p90 over 132 warmed lines and about 490 MB process RSS. It explicitly admits that intentional repetitions may be shortened. The existing contract processes a line/~512-token segment, so it cannot be adopted by silently splitting away Freehand's late corrections. A Windows GGUF/native conversion and tokenizer parity check are additional work.

[Super Cleanup](https://huggingface.co/Kayetic/super-cleanup-qwen3.5-2b) is a larger 2B MLX4-bit editor pruned to a 55k English/code vocabulary, about 800 MB. It uses context-rich training plus DPO against meaning errors. The published M5 Pro 185 ms median includes prompt-lookup speculative decoding and prefilling app context during recording; it is not CPU-only release-to-delivery evidence. Its 150 recent held-out model-judged real dictations still include 12 meaning errors.

### Muesli and rdsm/TalkMate

[Muesli's Qwen0.8B](https://huggingface.co/Muesli-HQ/qwen35-0.8b-muesli-cleanup-v12-gguf) is ready as Q4/Q8 GGUF, with 155k task pairs and synthetic held-out sets. Separate 2B, LFM1.2B and Gemma4 variants provide base-family controls. Their context-augmented tasks may be tested without screen context, but the exact trained role layout matters. WER against a cleaned reference and model-authored evaluation cannot prove semantic fidelity on Freehand.

[rdsm's Qwen0.8B](https://huggingface.co/rdsm/Qwen3.5-0.8B-parakeet-52k-FullFT), [LFM350](https://huggingface.co/rdsm/LFM2.5-350M-Base-parakeet-150k-FullFT) and [Smol360](https://huggingface.co/rdsm/SmolLM2-360M-parakeet-150k-FullFT-MLX-8bit) are full task fine-tunes. Published 100-case model-judged semantic figures are 81%, 72% and 71%, respectively. Under that rubric doing nothing scores 91%, a warning against treating average cleanup scores as faithful editing. [TalkMate's 5-bit artifact](https://huggingface.co/TalkMate/Qwen3.5-0.8B-parakeet-52k-FullFT-MLX-5bit) is a conversion of the same rdsm Qwen checkpoint, not a new trained model.

### Mumble, Evoo and other compact Qwen editors

[Mumble v1](https://huggingface.co/adikuma/mumble-cleanup) is Qwen2.5-0.5B with ready INT8 ONNX (~496 MB) and a 688-pair synthetic training set. It is intended for <=512-token input and can over-correct deliberate fragments. [Mumble 2stage](https://huggingface.co/amitashwini/mumble-cleanup-2stage) and its [Q4_0 export](https://huggingface.co/trevornk/mumble-cleanup-2stage-GGUF) are distinct from v1 but the export is not an independent model. One Pixel 10a observation improves from a >15 s Q4_K_M abort to ~2.9 s Q4_0, illustrating that a quantization with a fast hardware kernel may beat a nominally more sophisticated quantization.

[Evoo AI v1](https://huggingface.co/e2chndr/evoo-ai-v1) is an October 2026 Qwen0.6B task fine-tune trained on an 8 GB M1. Its own source shows the importance of pipeline boundaries: the model alone handles spoken corrections poorly, while Evoo's rules resolve many first. It reports about 0.30–0.41 s per dictation in the app's M1 llama.cpp path, but real failure-report performance is still weak and the rules+model pipeline needs separate evaluation.

[Orbal](https://huggingface.co/Orbalapp/orb-1-mini), [Vedu Scribe](https://huggingface.co/heyvedu/vedu-scribe-0.8b), [Transcrib Cleanup](https://huggingface.co/NicolaiMTLassen/transcrib-cleanup-0.6b), [VoiceInk Refine Mini](https://huggingface.co/beingpax/VoiceInk-Refine-Mini), [Mavery Lehrling](https://huggingface.co/rhymeas/Mavery-Lehrling-0.8B-MLX-4bit), [FlowScribe](https://huggingface.co/Abdullahu5mani/flowscribe-qwen2.5-0.5b-v2) and [Boswell](https://huggingface.co/meetboswell/boswell-dictation-cleanup) are further genuine small-editor leads. Most are MLX-only at their canonical repositories or have smaller/less complete evaluation evidence. They belong in the conversion/second-wave pool rather than being mistaken for immediately verified Windows solutions.

### Quantization may remove the learned correction behavior

[SimpleWords v2](https://huggingface.co/ReFyneLabs/simplewords-dictation-cleanup-v2) reports a sharp problem: fusing/requantizing its LoRA delta at 4 bits collapses held-out self-correction from 100% to 57.8%, while filler removal and validation loss still look good. Its 8-bit fused model is about 2 GB. [v3](https://huggingface.co/ReFyneLabs/simplewords-dictation-cleanup-v3) fixes cross-sentence corrections and reports 77% on an out-of-distribution Disfl-QA diagnostic, but explicitly ships a regression on one chained-correction case. These models are useful quality/training references, not evidence that every 4-bit version retains the behavior of its high-precision parent. Kanso similarly warns that merging its live adapter damages money formatting/filler behavior.

## Terms and explicit exclusions

- **LFM-derived models:** the LFM Open License v1.0 remains relevant even where a fine-tuner labels their modifications MIT or Apache. Its commercial revenue condition is not ordinary Apache. Exact text is preserved at the pinned [LiquidAI base revision](https://huggingface.co/LiquidAI/LFM2.5-350M/blob/9e6c6ccf47cd318696e137d381a7ded8fe4df09f/LICENSE). Retain notices and identify modifications. ScribeKey adds model naming/attribution and preserves Sotto notices.
- **[Fluid-1](https://huggingface.co/altic-dev/Fluid-1-Pico-0.8B-MLX-6bit):** exact ALTIC terms limit use to official FluidVoice apps and prohibit third-party use/integration/redistribution/modification without permission. It is an architecture reference; do not download its weights for a Freehand POC under an assumption that the Apache base permits it.
- **[Glimpse C1](https://huggingface.co/Glimpse-Dictation/Glimpse-C1-2B):** the Apache Bonsai base is separate from C1's restricted adapter. Personal noncommercial use is allowed, while product integration, commercial use, redistribution and output-based training need written permission.
- **[Amnis Light](https://huggingface.co/DRTR-J/amnis-light-cleanup-en-v1):** public download terms permit dictation through Amnis and do not grant reuse/redistribution in other apps. Its card candidly shows dropped commitments and unresolved corrections. It is a comparative product reference, not a directly reusable Freehand checkpoint.
- **[EG-1](https://github.com/saurabhav88/EnviousWispr/blob/main/EG-1-MODEL-LICENSE.txt):** the primary community license permits personal/research/evaluation benchmarking but restricts redistribution, commercial-product use and output-based commercial model training. It is a 4B Qwen derivative rather than an ultratiny replacement. The live GitHub license was read; a new immutable local snapshot could not be acquired through the cloud proxy in this subtask. Product-research evidence may supply one.
- **[ExecuWhisper Formatter](https://huggingface.co/younghan-meta/LFM2.5-350M-ExecuWhisper-Formatter):** CC-BY-NC metadata means it is not an ordinary commercial shipping candidate; upstream LFM terms also need tracing.
- **[Petal w1](https://huggingface.co/Aayush9029/petal-w1):** intentionally condenses rambles to roughly half their length. The published real-set error-free rate is 45–47%; this is the wrong editing policy for Freehand's faithful minimal cleanup, regardless of speed.
- **[Ivy Dictation](https://huggingface.co/raj7676/ivy-dictation):** audio ASR derivative, not a text postprocessor. **[Qwen3 ASR Refiner](https://huggingface.co/Aye10032/Qwen3-ASR-Refiner-0.6B)** is text-in/text-out despite its name, but trained for Chinese spoken-to-formal writing, not our English minimal edit.
- **Missing/conflicting declarations:** OpenWispr's GGUF card, Aide and GetOnIt need clearer weight terms/contracts. Bol's Apache badge on an LFM base does not erase inherited LFM conditions. Absence of a standalone license text is recorded; an app's source-code license must not be substituted for model terms.

## How to test this pool without repeating the earlier mistake

1. Freeze each checkpoint, precision and its *own* input contract. Preserve templates, tokenizer, license/notice files and all actual outputs. Never use a single general system prompt as the sole comparison across task-trained specialists.
2. Run a short operational screen on shared development cases: dictated questions/commands, hedges, negation, meaningful repetition, raw and normalized numbers, final-value corrections, very long late corrections, Unicode/code/paths, already-clean text and filler-only text. Empty output can be a legitimate model result while Freehand currently falls back; report that difference explicitly.
3. Run real dictionary replacements, including whitespace and a superseded protected clause. Evaluate the opaque-literal adapter independently of editing quality. Do not move/reapply dictionary normalization silently to improve a score.
4. Measure full-response latency and actual simultaneous process-tree memory, not file size or first token. Pin context/cache settings and include startup, cancellation, unloading and multiple model calls. Profile Windows CPU and the user's GPU separately; Apple Silicon/Vulkan-phone results are leads, not transferred SLAs.
5. Preserve both usefulness and harm: unneeded changes to clean text, incorrect deletion of emphasis, missed correction collapse, assistant answers, exact literal failures, fallback rate and plain-text presentation violations. A tiny model that always returns its input is fast and faithful but does not perform cleanup.
6. Treat the previously opened 30-case split as regression/validation now. Reserve a **new** locked final set, including real consented dictations with human-approved edits, before claiming a production winner. Published synthetic/token-accuracy scores cannot substitute for it.
